# NovaDesk 网页版

一个横屏的电脑式操作系统，跑在浏览器的 Canvas 里。

**打开方式：双击 `NovaDesk.html`。** 单文件、约 147 KB、零依赖、不用装东西、不用起服务器。

---

## 开机是什么样

进去先是**欢迎页**，只有两样东西：

```
        Welcome to NovaDesk          <- 一行白色斜体加粗艺术字（带黑描边）
        ┌──────────────────┐
        │ 输入指令，如 terminal │      <- 一个输入框
        └──────────────────┘
```

在输入框里敲**英文指令**，回车就打开对应的窗口：

| 指令 | 打开 |
|---|---|
| `terminal` | 终端 |
| `files` | 文件管理器 |
| `about` | 关于本机 |
| `clock` | 时钟 |
| `notes` | 记事本 |
| `paint` | 画板 |
| `help` | 列出所有指令 |
| 直接回车 | 进系统并开一个终端 |

也支持 `open terminal` 这种写法，以及中文别名（`终端`、`文件`……）。
敲错了会在输入框下面显示一行红字提示。

进入桌面后：拖标题栏移动窗口、拖右下角缩放、点红/黄/绿三点关闭/最小化/最大化、
点左下角开始按钮开菜单、点任务栏切换窗口。

## 退出再进来，东西都还在

网页本身没有内存，一刷新就重来。NovaDesk 把整个系统状态写进浏览器的
`localStorage`，所以**退出页面再进来，一切照旧**：

- 用户名
- 开着的每个窗口（位置、大小、是否最大化、是否最小化）
- 终端里的滚屏内容和历史命令
- 记事本正文
- 画板上的涂鸦
- 你自己创建的文件

实现上，内核只通过那 8 个系统调用里的文件接口读写存档
（`open` / `write` / `close`），内核自己**不碰** `localStorage` ——
宿主（浏览器）才负责落地。这样存档机制在安卓宿主上同样能用。

要清空重来：在浏览器控制台里执行 `localStorage.clear()` 然后刷新。

## 中文是怎么做的

原版只有 5x7 的 ASCII 点阵字库，中文字会显示成空心方块。
现在系统自带一套**中文点阵字库**：

- 从源码的字符串字面量里抽出所有用到的汉字（**不包含注释**，
  否则字库会白白大出一大截：685 字 -> 189 字）
- 用 GDI+ 把每个字渲染成点阵，**关掉抗锯齿**，因为内核只有 1 位/像素
- 字体是 **Microsoft YaHei @ 20px**。选它是因为笔画有 2px 粗，
  缩到手机上仍然清楚；SimSun 的 1px 笔画一缩放就糊了
- 所有字形统一裁到**同一个包围盒**（并留 1px 余量），
  这样它们之间的基线和相对位置才一致
- 结果：每个字 **23x23** 点阵，189 个字，约 26 KB

行高按中文算（23px），ASCII 通过 `Font.ASCII_DY` 下沉对齐到中文基线。
未收录的字会画成一个**方框加中心点**，而不是静默消失 —— 缺字要看得见。

重新生成字库（改了界面文字之后）：

```powershell
python web/build-cjk.py
python web/build-bundle.py
```

## 分辨率为什么是 800x450

不是 1280x720。因为中文字形有 23 像素高，虚拟分辨率越低，
它在屏幕上占的比例越大：手机横屏大约 700x390 CSS 像素，
800x450 缩放过去中文差不多 14 CSS 像素，刚好能读。
用 1280x720 的话中文只剩 10 像素左右，看不清。

窗口默认尺寸仍按原来的 1280x720 设计，`launch()` 里按屏幕高度
等比缩放（`uiScale = screen.h / 720`），所以应用代码不用改。

## 源码结构（`web/`）

| 文件 | 作用 |
|---|---|
| `kernel-core.js` | 光栅化器、字库、窗口、VFS、App 基类、ABI 事件、艺术字 |
| `kernel-cjk.js` | **自动生成**的中文点阵字库，不要手改 |
| `kernel-apps.js` | 六个应用 + 各自的状态保存/恢复 |
| `kernel.js` | 内核：调度、输入分发、合成、任务栏、欢迎页、指令、存档 |
| `host.js` | 浏览器宿主，实现那 8 个系统调用 |
| `boot.js` | 开机、主循环、事件翻译 |
| `gen-cjk.ps1` | 用 GDI+ 渲染汉字点阵（**必须保持纯 ASCII**） |
| `build-cjk.py` | 抽字 -> 渲染 -> 裁剪 -> 生成 `kernel-cjk.js` |
| `build-bundle.py` | 把上面这些打包成单个 `NovaDesk.html` |

生成链：`gen-cjk.ps1` -> `build-cjk.py` -> `build-bundle.py` -> `NovaDesk.html`

> `gen-cjk.ps1` 里请**不要**写中文。Windows PowerShell 5.1 按 ANSI 读脚本，
> 中文会在运行前就被破坏；中文一律通过 UTF-8 数据文件传进去。

## 验证

不是"看着像"，而是用无头 Edge 真跑起来读像素断言：

```powershell
cd web
python verify-cn.py        # 20 项断言
python build-cjk.py        # 重新生成字库
python build-bundle.py     # 重新打包
```

`verify-cn.py` 覆盖：

| 组 | 检查 |
|---|---|
| 1 开机 | 进的是欢迎页、没有窗口、大字已渲染、800x450、字库已载 |
| 2 字库 | 界面用到的中文全都有字形、抽查常用字命中 |
| 2b 缺字 | 未收录字画成可见方框，不是消失 |
| 3 指令 | 输入 `terminal` 进桌面、开出一个窗口、标题是中文 |

| 6 存档 | 刷新后记住用户名、窗口、终端 22 行内容、文件内容 |

当前结果：**20 项全过**。

## 移植时踩过的坑

1. **PowerShell 的 `-shl` 是 Int32 运算**。格子大于 31 像素时
   `1 -shl 39` 会被掩成 `1 -shl 7`，整张点阵全乱。必须转 `[long]`。
2. **PowerShell 5.1 按 ANSI 读 `.ps1`**，脚本里的中文会在运行前就损坏。
   所以脚本保持纯 ASCII，中文走数据文件。
3. **PNG 的 alpha 不能丢**。内核大量使用半透明色（如桌面图标底色
   `0x18FFFFFF`），解码截图时若把 alpha 强行设成 `0xFF`，
   所有半透明像素都会被误判成"和参考图不一致"。
4. **`ImageData` 的通道顺序**：内核像素是 ARGB，小端机上读成 `Uint32`
   是 `0xAABBGGRR`，R 和 B 必须对调，否则红蓝互换。
5. **艺术字要先裁到墨迹再居中**。不裁的话画布里大部分是行高留白
   （ASCII 只占 7 行，行高按中文算有 23 行），
   字看着比预期小，居中也会偏。

## 已知限制

- 纯软件渲染，800x450 每帧全量重算，手机上可能偏慢
- 字库只收录了界面实际用到的 189 个汉字；写新的中文界面文字后
  需要重跑 `build-cjk.py`
- 单线程协作式调度，没有真正的进程隔离
- 没有网络、麦克风、摄像头 —— 目前是一个封闭的小系统
- 中文输入依赖系统输入法（通过一个隐藏的 `<input>` 转接）

## 下一步：接入 AI

目标是让 NovaDesk 像一个 AI 系统那样，在系统里直接开一个对话窗口，
接 DeepSeek，能按需生成小工具/插件。

需要注意的技术点：

- **API key 由用户自己填**，存在浏览器里，不写死在文件中
- **浏览器直连接口有跨域（CORS）限制**，DeepSeek 的接口不一定允许
  浏览器直接调用；如果不行，需要一个本地小代理转发
- 在浏览器里持有 key 本身有暴露风险，只适合个人本地使用

## 与安卓版的关系

| | 安卓版 | 网页版 |
|---|---|---|
| 宿主 | `nova/host/*.kt` | `web/host.js` + `boot.js` |
| 内核 | `nova/kernel/*.kt` + `nova/apps/*.kt` | 翻译成 JS |
| 产物 | `app-debug.apk` | `NovaDesk.html` |
| 中文 | 还没有 | 有 |

内核最初就是按"可以换宿主"设计的。这次移植加中文化证明了这条线是对的：
**换掉宿主、换掉字体，内核照跑。**
